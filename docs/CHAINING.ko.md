# 압축 뒤에도 각 세션의 작업 이어가기

[English](CHAINING.md) · [문서 목록](README.ko.md) · [작업 상태](CONTINUATION.ko.md)

세션 체이닝은 각 Codex 세션이 자기 작업을 계속하도록 돕습니다.
세션을 처음 시작하면 자동으로 준비합니다.
문맥을 압축하기 전에 자기 작업 기록을 저장합니다.
압축 뒤에는 그 기록을 같은 세션의 다음 모델 입력에 넣습니다.
사용자가 세션을 닫으면 마지막 기록을 저장하고 종료합니다.

세션 하나만 사용해도 동작합니다.
A·B·C 세션을 함께 사용하면 각 세션은 자기 기록만 복원합니다.
다른 세션과의 협업은 기존 메시징 도구로 처리합니다.
체이닝은 다른 세션의 작업을 가져오거나 새 세션을 열지 않습니다.

## 사용

1. [업데이트 안내](OPERATIONS.ko.md)에 따라 플러그인을 갱신하세요.
2. Codex `/hooks`에서 플러그인 훅을 검토하세요.
3. 사용할 훅을 신뢰하도록 설정하세요.
4. 현재 프로젝트에서 작업을 계속하세요.

체인 이름이나 연결 명령을 지정할 필요가 없습니다.
[프로젝트 지침](PROJECT_GUIDANCE.ko.md)에 따라 현재 AGENTS 본문도 직접 넣습니다.
읽으라는 안내문만 보내지 않습니다.
일반 후속 입력에는 같은 본문을 계속 덧붙이지 않습니다.
시작하거나 문맥을 복구할 때 파일을 다시 읽습니다.

## 이벤트별 동작

| 이벤트 | 동작 |
|---|---|
| SessionStart / startup | 자기 세션 ID와 프로젝트를 확인하고 자동 저장 상태를 준비합니다. |
| PreCompact | 압축 직전의 자기 작업 기록을 저장합니다. |
| SessionStart / compact | 자기 기록과 현재 AGENTS 본문을 다음 모델 입력에 넣습니다. |
| Stop | 끝난 턴의 자기 기록을 저장합니다. |
| SessionEnd | 마지막 기록을 저장하고 종료 상태를 남깁니다. |
| SessionStart / resume | 사용자가 같은 세션을 다시 열면 자기 기록만 복원합니다. |
| SessionStart / clear | 이전 작업을 다시 넣지 않도록 문맥 저장 범위를 초기화합니다. |

종료 훅은 다른 Codex 프로세스나 세션을 시작하지 않습니다.
사용자가 닫은 세션을 자동으로 다시 열지 않습니다.
복원은 추가 작업 실행을 승인하거나 Stop의 자동 실행 조건을 다시 켜지 않습니다.

## 세션을 섞지 않는 방법

저장 상태와 체크포인트에 세션 UUID와 프로젝트 경계를 함께 기록합니다.
체크포인트는 특정 시점의 작업 기록 파일입니다.
복원할 때 두 값이 현재 세션과 일치하는지 검사합니다.
Git 프로젝트는 현재 worktree의 실제 루트를 사용합니다.
공통 Git 폴더로 서로 다른 worktree를 묶지 않습니다.
검증에 실패하면 해당 기록을 복원하지 않습니다.
최근 수정 시각이나 세션 이름으로 다른 기록을 대신 고르지 않습니다.

## 저장하는 내용

- 처음 확인한 사용자 메시지 기록
- 최근 사용자·어시스턴트 메시지 기록
- 해당 세션의 작업 상태 보고
- 완료로 보고한 항목과 남은 체크리스트 항목
- 제한된 Git 상태

처음 요청을 확인할 수 없으면 그 상태를 표시합니다.
최근 메시지를 처음 요청이라고 추정하지 않습니다.
자동 대화 기록에는 크기와 읽기 범위 제한이 있습니다.
복원 기록이 길면 문맥 한도에 맞춰 줄이고 축약 표시를 넣습니다.
저장한 체크포인트 원문은 바꾸지 않습니다.
세션은 `set_work_state`로 목표와 남은 작업, 근거를 갱신할 수 있습니다.
구조화된 작업 보고가 없으면 자동 기록만 복원했다는 표시를 넣습니다.

복원 기록은 이전 대화와 모델 보고입니다.
모델의 완료 보고는 독립적으로 검증한 완료가 아닙니다.
동료 메시지와 이전 기록은 새로운 사용자 명령이나 승인이 아닙니다.
현재 사용자의 요청과 세션 권한이 계속 적용됩니다.
AGENTS 파일은 별도로 읽습니다.
AGENTS 본문을 과거 작업 기록으로 대신하지 않습니다.

## 상태 확인

현재 세션에서 `get_chain`을 호출하면 자기 자동 저장 상태를 조회합니다.
이 도구 이름은 이전 설치와의 호환성을 위해 유지합니다.
`chain status`와 `chain doctor`도 조회에 사용할 수 있습니다.
상태 조회만으로 훅 실행이나 모델의 지침 준수를 입증하지는 않습니다.
`chain doctor`는 훅 등록·활성화·신뢰 상태를 따로 표시합니다.

```text
node plugins/cross-session/src/cli.mjs chain status --session YOUR_SESSION_UUID
node plugins/cross-session/src/cli.mjs chain doctor
```

사용자의 세션 UUID로 자리표시자를 바꾸세요.
MCP의 호출자 UUID는 Codex가 제공한 정보로 확인합니다.
모델이 다른 세션 UUID를 지정해서 작업을 가져올 수는 없습니다.

## 이전 버전에서 갱신

이전 버전의 다른 세션 연결 방식은 제품 의도를 잘못 반영했습니다.
현재 버전은 각 세션의 자동 문맥 유지로 범위를 바로잡습니다.
`link_chain`, `unlink_chain`, `relink_chain`은 공개 도구 목록에서 제거했습니다.
이전 연결 명령과 `chain launch` 호출은 오류로 거부합니다.
거부한 호출은 티켓이나 세션을 만들지 않습니다.

새 기록은 메시지 저장 폴더 안의 `session-continuity-v1`에 저장합니다.
이전 `chaining-v1` 파일은 그대로 보존합니다.
새 복원 경로는 이전 연결이나 티켓을 읽지 않습니다.
이전 기록을 새 세션의 기록으로 자동 변환하지 않습니다.

## 파일과 실패 처리

기록은 로컬 파일에 평문으로 저장됩니다.
주의: 작업 기록에 비밀 정보를 넣지 마세요.
복원한 기록과 AGENTS 본문은 설정한 모델 제공자에게 전달될 수 있습니다.
플러그인은 기록을 만들려고 외부 모델을 별도로 호출하지 않습니다.

파일 쓰기에는 잠금과 원자적 교체를 사용합니다.
기록 크기와 개수, 실행 시간에는 한도가 있습니다.
브로커 훅은 상태 조회와 시작 대기, 실제 요청에 하나의 제한 시간을 적용합니다.
브로커 전체 제한은 시작 때 5초, 사용자 입력 때 3초입니다.
Stop·Interrupt·SessionEnd의 브로커 제한은 1.8초입니다.
호스트 제한은 프로세스 시작과 종료 시간을 포함해 시작 때 10초, 나머지 이벤트 때 5초입니다.
저장 실패를 성공으로 표시하지 않습니다.
실패한 복원을 다른 세션의 기록으로 대체하지 않습니다.
체이닝 저장 오류와 AGENTS 읽기 오류는 각각 표시합니다.
각 오류는 기존 메시징 전달 경로와 따로 처리합니다.

본문이 모델 입력에 들어간 사실은 검증할 수 있습니다.
모델이 모든 지침을 기억하거나 따랐다는 보장은 할 수 없습니다.
