# 배포 확인표

[English](RELEASE.md)

현재 배포 형태는 로컬 원본 마켓플레이스의 Codex 플러그인입니다.
npm 패키지는 비공개 패키지로 설정되어 있습니다.
이 저장소는 npm 패키지나 호스팅 서비스를 공개하지 않습니다.
이 확인표는 릴리스가 공개되었다고 주장하지 않습니다.

## 후보 준비

1. 배포 담당자는 루트 패키지와 플러그인 패키지와 잠금 파일 루트와 플러그인 설정의 버전을 일치시킵니다.
2. 배포 담당자는 `LICENSE`를 포함합니다.
3. 배포 담당자는 패키지 라이선스 필드의 `MIT`를 확인합니다.
4. 배포 담당자는 두 README 파일의 상대 링크를 확인합니다.
5. 배포 담당자는 설치와 업데이트와 삭제 안내를 현재 스크립트에 대조합니다.
6. 배포 담당자는 `npm ci --prefix plugins/cross-session --ignore-scripts`로 의존성을 설치합니다.
7. 배포 담당자는 `npm run check`를 실행합니다.
8. 배포 담당자는 `npm test`를 실행합니다.
9. 배포 담당자는 [검증 안내](VERIFICATION.ko.md)의 격리된 실제 Codex 통합 테스트를 실행합니다.
10. 배포 담당자는 임시 `CODEX_HOME`에 설치를 시험합니다.
11. 배포 담당자는 해당 임시 설정 폴더에서 삭제를 시험합니다.
12. 배포 담당자는 해당 임시 설정 폴더에서 보존 옵션과 정리 옵션을 시험합니다.
13. 배포 담당자는 관련 없는 Codex 파일의 보존을 확인합니다.
14. 배포 담당자는 설정된 Windows와 macOS CI 작업을 실행합니다.
15. 배포 담당자는 버전과 결과와 생략한 검사와 호환성 제한을 기록합니다.
16. 배포 담당자는 후보에 비공개 파일이나 개인 경로나 토큰이나 메시지 기록이 없는지 확인합니다.
17. 배포 담당자는 최종 diff의 독립 검토를 받습니다.

버전 값은 브로커 구현과 네이티브 클라이언트 구현에도 있습니다.
제품 버전을 바꿀 때는 해당 값도 확인합니다.
배포 파일에는 플러그인 설정과 MCP 설정과 훅과 배포 스킬과 원본 코드와 의존성 잠금 파일이 포함되어야 합니다.
마켓플레이스 원본은 `plugins/cross-session`으로 해석되어야 합니다.
원본 설치 후 설치된 캐시에는 실행 의존성이 포함되어야 합니다.
플러그인 폴더는 저장소 루트와 같은 MIT 라이선스 원문을 포함해야 합니다.
Windows 정리 검사는 8.3 경로 별칭과 별칭 조회 실패를 확인해야 합니다.
두 조건 모두 실행 데이터를 보존해야 합니다.
최초 데이터 정리 검사 실패는 설치된 플러그인도 보존해야 합니다.

## 지원 준비

1. 배포 담당자는 GitHub 비공개 취약점 보고를 활성화합니다.
2. 배포 담당자는 이슈 링크와 보안 보고 링크를 확인합니다.
3. 배포 담당자는 최종 후보의 [변경 기록](../CHANGELOG.ko.md)을 갱신합니다.
4. 배포 담당자는 운영체제 제한과 Codex 프로토콜 제한을 문서에 기록합니다.
5. 배포 담당자는 시험한 업데이트 경로와 삭제 경로를 문서에 기록합니다.

배포 담당자는 [검증 안내](VERIFICATION.ko.md)에서 CI 기준 결과의 commit과 실행 환경을 확인합니다.
설정된 작업 흐름은 CI 실행 성공의 증거가 아닙니다.
통합 테스트는 로컬 모형 모델을 사용합니다.
통합 테스트는 실제 모델이 요청한 작업을 완료한다고 증명하지 않습니다.

## 승인 후 공개

1. 배포 담당자는 모든 후보 검사가 통과했거나 제한이 명시적으로 기록되었는지 확인합니다.
2. 배포 담당자는 승인된 버전 태그를 만듭니다.
3. 배포 담당자는 승인된 commit과 태그를 push합니다.
4. 배포 담당자는 호환성과 삭제 링크를 포함한 릴리스 설명을 공개합니다.

저장소 수정과 로컬 commit은 push나 공개 승인을 뜻하지 않습니다.
push는 릴리스 태그를 만들지 않습니다.
push는 GitHub 릴리스를 만들지 않습니다.
push는 마켓플레이스 공개를 수행하지 않습니다.
