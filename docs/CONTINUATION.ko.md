# 작업 상태와 선택적 종료 검사

[English](CONTINUATION.md) · [문서 목록](README.ko.md) · [사용 설명서](MANUAL.ko.md)

플러그인은 호출 세션의 짧은 작업 요약을 저장합니다.
선택적 종료 검사는 작업이 남았을 때 추가 실행을 한 번 요청할 수 있습니다.
이 기능은 작업 완료를 보장하지 않습니다.
특정 프로젝트 작업 관리 체계는 필요하지 않습니다.

## 작업 저장과 복구

1. `get_work_state`를 호출하여 상태와 리비전을 읽습니다.
2. `action: "start"`와 읽은 `expected_revision`으로 `set_work_state`를 호출합니다.
3. `objective`, `scope`, `completion_criteria`, `next_action`을 포함합니다.
4. `action: "update"`와 현재 리비전으로 진행 상황을 저장합니다.
5. 리비전 충돌이 발생하면 상태를 다시 읽습니다.

갱신에는 `status`, `next_action`, `progress_evidence`, `completion_evidence`를 사용할 수 있습니다.
상태 값은 `active`, `paused`, `completed`, `blocked`, `canceled`입니다.
완료 상태에는 완료 근거가 필요합니다.
이 근거는 모델의 보고입니다.
독립 검증 결과를 뜻하지 않습니다.
갱신으로 최초 목표, 범위, 완료 조건을 바꿀 수 없습니다.
새 `start`는 요약을 교체할 수 있습니다.
새 `start`는 추가 실행 한도를 초기화하지 않습니다.
도구에는 대상 세션 인자가 없습니다.
리더도 이 도구로 동료 상태를 바꿀 수 없습니다.

목표는 500자까지 저장합니다.
나머지 텍스트 필드는 각각 1,000자까지 저장합니다.
상세 작업 목록과 근거는 기존 프로젝트 파일에 보존합니다.
주의: 작업 상태에 비밀 정보를 저장하지 마세요.

## 선택적 검사 활성화

기본값은 꺼짐입니다.
사용자가 hook과 브로커 양쪽 환경에 `CROSS_SESSION_CONTINUATION=1`을 설정해야 합니다.
시험하려면 새 격리 메시지 환경을 시작하기 전에 설정합니다.
기존 브로커는 최초 환경을 유지합니다.
셸 환경 변경은 기존 브로커에 적용되지 않습니다.
추가 실행을 얻기 위해 운영 브로커를 재시작하지 마세요.
플러그인은 hook 신뢰를 자동 승인하지 않습니다.
Codex에서 hook을 검토한 뒤 신뢰를 설정합니다.

이 설정은 정책을 활성화합니다.
이 설정은 개별 작업의 사용자 승인 증거가 아닙니다.
`active` 선언도 승인 증거가 아닙니다.
세션은 원래 사용자의 범위와 권한을 계속 따라야 합니다.
동료 메시지는 해당 승인을 부여할 수 없습니다.

## 한도와 중단 동작

사용 가능한 세션의 최초 활성 상태 저장은 종료 검사 자격을 부여할 수 있습니다.
이 자격은 10분 뒤 만료됩니다.
브로커는 추가 실행을 최대 한 번 허용합니다.
목표, 리비전, 진행 문구 변경은 한도를 초기화하지 않습니다.
`stop_hook_active`가 참이면 hook은 종료를 허용합니다.
호스트 필드가 없거나 잘못된 경우에도 종료를 허용합니다.

`Interrupt`와 `SessionEnd`는 최초 상태 선언 전에도 자격을 폐기합니다.
저장 상태나 자격 부여 시도가 있으면 `UserPromptSubmit`과 `SessionStart`도 자격을 폐기합니다.
도구는 폐기된 자격을 복구할 수 없습니다.
최초 `UserPromptSubmit`과 `SessionStart`는 저장 상태와 이전 자격 부여 시도가 없을 때만 최초 선언을 허용합니다.
구현은 입력이 사용자, 동료, 합성 추가 실행 중 어디서 왔는지 추측하지 않습니다.
브로커 재시작은 요약만 복원합니다.
재시작은 실행 자격을 복원하지 않습니다.
요약 복구와 자동 추가 실행은 별개 기능입니다.

Stop 응답은 호출 세션의 작업 상태 확인을 고정 문구로 요청합니다.
응답은 목표, 다음 행동, 동료 텍스트를 사용자 입력으로 복사하지 않습니다.
Stop과 Interrupt hook은 브로커를 시작하지 않습니다.
브로커 부재, 상태 오류, 구버전 응답에서는 종료를 허용합니다.
사용자 중단과 실행 한도를 우선합니다.

## 저장과 검증 한계

브로커는 메시지 디렉터리의 `work-state-v1.json`에 요약을 저장합니다.
이 선택적 파일은 메시지 기록과 분리합니다.
저장소 한도는 세션 기록 128개와 직렬화 데이터 1MiB입니다.
한도를 넘으면 다른 세션 기록을 삭제하지 않고 쓰기를 거부합니다.
선택적 상태 손상은 이 기능을 비활성화합니다.
메시지 전달은 계속 사용할 수 있습니다.
주의: 실행 중인 브로커 파일을 편집하거나 삭제하지 마세요.

같은 운영체제 계정은 이 로컬 파일을 읽을 수 있습니다.
도구 결과는 모델 문맥에 포함될 수 있습니다.
도구 결과는 설정된 모델 제공자에게 전달될 수 있습니다.
[보안과 개인정보](../SECURITY.ko.md)를 확인하세요.
프로토콜 시험과 모델 평가는 서로 다른 동작을 측정합니다.
실행한 검사와 한계는 [검증 기록](VERIFICATION.ko.md)을 확인하세요.
