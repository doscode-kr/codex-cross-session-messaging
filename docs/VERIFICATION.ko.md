독립 검증자는 2026-10-08에 통합 후보 검사를 실행했습니다.

|---|---|
| 운영체제와 셸 | Windows PowerShell |
| Node.js | 20.19.4 |
| Python | 3.12.1 |

| 명령 | 종료 코드 | 결과 |

| `npm run check` | 0 | 구문과 JSON과 버전과 라이선스와 필수 파일과 문서 링크 검사가 통과했습니다. |
| 해당 프로세스에 `CROSS_SESSION_REAL_CODEX_TEST=1`을 지정한 `npm test` | 0 | 총 44개 중 43개 통과, 실패 0개, 생략 1개입니다. |
| `git diff --check` | 0 | 공백 오류가 없습니다. |

유지관리자는 같은 날짜에 의존성 검사를 실행했습니다.
해당 결과는 당시 확인할 수 있었던 의존성 보안 권고를 기준으로 합니다.

실제 Codex 통합 테스트는 작업 중인 수신 세션의 `turn/steer` 전달을 통과했습니다.
실제 Codex 통합 테스트는 대기 중인 수신 세션의 `turn/start` 전달을 통과했습니다.
설치 테스트와 삭제 테스트는 임시 Codex 설정 폴더에서 통과했습니다.
반복 삭제가 통과했습니다.
관련 없는 설정과 플러그인과 캐시의 보존이 통과했습니다.
통합 테스트는 로컬 모형 모델 서버를 사용했습니다.
통합 테스트는 실제 모델 API를 호출하지 않았습니다.
통합 테스트는 사용자의 일반 Codex 설정 폴더를 변경하지 않았습니다.

`a broker that starts during inventory prevents runtime purge` 테스트는 생략했습니다.
해당 테스트는 8.3 실행 데이터 경로 별칭을 감지했습니다.
해당 테스트는 목록 조회의 시간 제어 지점 전에 생략했습니다.
자동 정리는 해당 경로의 삭제를 거부합니다.
생략한 테스트는 통과한 43개에 포함하지 않습니다.
따라서 이번 실행은 목록 조회 시작 후의 해당 시간 조건을 검증하지 않았습니다.

이 결과는 통합 후보의 결과입니다.
코드 변경 후에는 배포 검사를 다시 실행합니다.
남은 운영체제 검사와 공개 배포 검사는 [배포 확인표](RELEASE.ko.md)를 사용합니다.

## 기본 검사


기본 테스트 명령은 명시적 실행 변수를 지정하지 않으면 `tests/real-codex.test.mjs`를 생략합니다.

## 격리된 실제 Codex 통합

테스트는 두 독립 세션을 가진 실제 Codex App Server를 시작합니다.
테스트는 임시 `CODEX_HOME`을 사용합니다.
테스트는 로컬 컴퓨터의 loopback 모형 모델 서버를 사용합니다.
테스트는 설치된 MCP 도구의 조회를 확인합니다.
테스트는 작업 중인 세션과 대기 중인 세션의 동료 메시지 본문이 모델 요청에 포함되는지 확인합니다.
테스트는 실제 모델 API를 호출하지 않습니다.

PowerShell:

```powershell
$previousIntegrationSetting = $env:CROSS_SESSION_REAL_CODEX_TEST
try {
    $env:CROSS_SESSION_REAL_CODEX_TEST = '1'
    npm test
} finally {
    if ($null -eq $previousIntegrationSetting) {
        Remove-Item Env:CROSS_SESSION_REAL_CODEX_TEST -ErrorAction SilentlyContinue
    } else {
        $env:CROSS_SESSION_REAL_CODEX_TEST = $previousIntegrationSetting
    }
}
```

macOS 셸:

```sh
CROSS_SESSION_REAL_CODEX_TEST=1 npm test
```

이 명령은 다음 실행을 위한 안내입니다.
기록된 Windows 결과는 위에 있습니다.
이 문서에는 macOS 실행 결과가 없습니다.

## 배포 후보 문서 검사

2026-10-08의 문서 작업은 Windows에서 `npm run check`와 `git diff --check`를 실행했습니다.
두 검사는 통과했습니다.
독립 상대 링크 검사는 Markdown 파일 15개의 로컬 링크 38개를 확인했습니다.
YAML 검사는 CI 작업 흐름과 오류 보고 양식을 읽었습니다.
루트 라이선스와 플러그인 라이선스 사본은 일치했습니다.
직접 실행한 `node scripts/install.mjs --dry-run`은 통과했습니다.
해당 명령은 예정된 의존성 설치와 마켓플레이스 등록과 플러그인 설치 명령을 출력했습니다.
해당 명령은 출력한 작업을 실행하지 않았습니다.

이 환경의 PowerShell에서 `npm run install:global -- --dry-run`은 설치 스크립트에 옵션을 전달하지 않았습니다.
해당 실행은 로컬 의존성을 설치했습니다.
이후 마켓플레이스 등록은 원본 충돌로 실패했습니다.
해당 실행은 플러그인 설치를 수행하지 않았습니다.
사용자는 설치 옵션을 지정할 때 직접 Node.js 명령을 사용합니다.
